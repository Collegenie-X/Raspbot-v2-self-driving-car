## 세부 평가 항목

### 1. rect 랜덤 좌표 생성 (총 8점)

#### 평가 목적
표지판(O)의 위치와 크기를 랜덤하게 생성하는 능력을 평가합니다. 이는 시뮬레이션의 다양성을 확보하는 핵심 기능입니다.

#### 세부 항목

**1-1. X좌표 랜덤생성 (2점)**
- **평가 기준**: 
  - `random` 모듈 사용 확인
  - x, x_pos, rect_x, pos_x, sign_x 등의 변수명 사용
  - 0~640 범위 또는 WIDTH 상수 사용
- **통과 조건**:
  ```python
  # 예시 1: 범위 지정
  x = random.randint(0, 640)
  
  # 예시 2: 상수 사용
  x = random.randint(X_MIN, X_MAX)
  ```
- **점수 부여**: 조건 충족 시 2점, 미충족 시 0점

**1-2. Y좌표 랜덤생성 (2점)**
- **평가 기준**: 
  - `random` 모듈 사용 확인
  - y, y_pos, rect_y 등의 변수명 사용
  - 0~480 범위 또는 HEIGHT 상수 사용
- **통과 조건**: X좌표와 동일한 패턴
- **점수 부여**: 조건 충족 시 2점

**1-3. 너비(width) 랜덤생성 (2점)**
- **평가 기준**:
  - `random` 모듈 사용
  - w, width, rect_w 등의 변수명
  - 50~150 범위 권장
- **점수 부여**: 조건 충족 시 2점

**1-4. 높이(height) 랜덤생성 (2점)**
- **평가 기준**: width와 동일한 패턴
- **점수 부여**: 조건 충족 시 2점

#### 왜 이렇게 평가하는가?
rect 좌표는 자율주행 시뮬레이션에서 표지판의 위치와 크기를 결정하는 핵심 요소입니다. 각 좌표를 독립적으로 평가하여 학생이 **2차원 좌표계**와 **객체 크기 개념**을 정확히 이해하고 있는지 확인합니다.

### 2. 위치 추적 로직 (총 3점)

#### 평가 목적
표지판의 X 좌표를 기반으로 화면을 좌/중/우로 구분하여 차량의 조향 방향을 결정하는 로직을 평가합니다.

#### 세부 항목

**2-1. 좌측 영역 판별 (1점)**
- **평가 기준**:
  ```python
  # 화면을 3등분하여 좌측 판별
  if x < 213:  # 640 / 3
      # 좌회전 또는 좌측 처리
  ```
- **인정 패턴**:
  - `x < LEFT` 또는 `x < 213`
  - `x < 640 / 3`
  - "left", "왼쪽", "좌측" 키워드와 함께 x 좌표 사용
- **점수 부여**: 패턴 발견 시 1점

**2-2. 중앙 영역 판별 (1점)**
- **평가 기준**:
  ```python
  elif 213 <= x < 427:  # 640 * 2 / 3
      # 직진 처리
  ```
- **인정 패턴**:
  - 범위 체크 (213 <= x < 427)
  - "center", "middle", "중앙" 키워드 사용
  - `elif` 문으로 중간 영역 처리
- **점수 부여**: 패턴 발견 시 1점

**2-3. 우측 영역 판별 (1점)**
- **평가 기준**:
  ```python
  else:  # x >= 427
      # 우회전 또는 우측 처리
  ```
- **인정 패턴**:
  - `x > RIGHT` 또는 `x >= 427`
  - "right", "오른쪽", "우측" 키워드 사용
- **점수 부여**: 패턴 발견 시 1점

#### 왜 이렇게 평가하는가?
위치 추적은 자율주행의 핵심 기능입니다. 화면을 3등분하여 객체의 위치를 판별하는 것은 실제 자율주행에서 **차선 인식** 및 **장애물 회피**와 유사한 개념입니다. 각 영역을 독립적으로 평가하여 학생이 **조건 분기**를 정확히 이해하고 있는지 확인합니다.

### 3. 거리 판단 로직 (총 4점)

#### 평가 목적
표지판의 width 크기를 기반으로 거리를 판단하는 로직을 평가합니다. 이는 실제 컴퓨터 비전에서 사용되는 원리입니다.

#### 세부 항목

**3-1. 원거리 판별 (2점)**
- **평가 기준**:
  ```python
  # width가 작으면 멀리 있음
  if width < 90:
      print("원거리 - 전진하여 접근")
  ```
- **인정 패턴**:
  - `width < 90` 또는 `width < FAR`
  - "far", "멀", "원거리" 키워드 사용
  - "small", "작" 등 크기 표현
- **점수 부여**: 패턴 발견 시 2점

**3-2. 근거리 판별 (2점)**
- **평가 기준**:
  ```python
  # width가 크면 가까이 있음
  if width >= 120:
      print("근거리 - 주차 시작")
  ```
- **인정 패턴**:
  - `width >= 120` 또는 `width > CLOSE`
  - "near", "close", "가까", "근거리" 키워드
  - "large", "big", "크" 등 크기 표현
- **점수 부여**: 패턴 발견 시 2점

#### 왜 이렇게 평가하는가?
거리 판단은 **원근법(perspective)**의 기본 원리를 이해하고 있는지 확인합니다. 카메라 이미지에서 객체의 크기로 거리를 추정하는 것은 실제 자율주행 시스템에서 핵심적인 기능입니다. 원거리와 근거리를 각각 2점으로 배점하여 **양방향 판단 능력**을 평가합니다.

### 4. 표지판 처리 로직 (총 2점)

#### 평가 목적
stop과 danger 표지판을 감지하고 적절히 대응하는 로직을 평가합니다.

#### 세부 항목

**4-1. stop 표지판 처리 (1점)**
- **평가 기준**:
  ```python
  if sign == "stop":
      print("정지 표지판 인식!")
      # 기어모터 정지
      # 부저 3회
      break  # 또는 continue, return
  ```
- **인정 패턴**:
  - "stop", "정지", "중지", "멈춤" 키워드
  - `break`, `continue`, `return`, `exit` 제어문 사용
  - `if...stop` 조건문
- **점수 부여**: 패턴 발견 시 1점

**4-2. danger 표지판 처리 (1점)**
- **평가 기준**: stop과 동일한 패턴
- **인정 패턴**:
  - "danger", "위험", "충돌" 키워드
  - 제어문과 함께 사용
- **점수 부여**: 패턴 발견 시 1점

#### 왜 이렇게 평가하는가?
표지판 처리는 **안전 제어 로직**의 핵심입니다. stop과 danger를 감지하고 즉시 주행을 종료하는 것은 실제 자율주행에서 **긴급 정지(emergency stop)** 기능에 해당합니다. 각 표지판을 독립적으로 평가하여 **예외 상황 처리 능력**을 확인합니다.

### 5. 주행 제어 로직 (총 4점)

#### 평가 목적
차량의 기본적인 주행 제어(전진, 좌회전, 우회전, 후진/정지)를 구현했는지 평가합니다.

#### 세부 항목

**5-1. 전진 주행 로직 (1점)**
- **평가 기준**:
  ```python
  def go_forward():
      print("차량이 직진합니다")
      # 또는
  if direction == "up":
      print("전진")
  ```
- **인정 패턴**:
  - `go()`, `forward`, `move_forward`, "전진", "앞" 키워드
  - `speed = 양수` 설정
  - "motor", "drive", "straight" 키워드
- **점수 부여**: 패턴 발견 시 1점

**5-2. 좌회전 제어 로직 (1점)**
- **인정 패턴**:
  - `turn_left()`, "left", "왼쪽", "좌회전" 키워드
  - `steer...left` 또는 `rotate...left`
- **점수 부여**: 패턴 발견 시 1점

**5-3. 우회전 제어 로직 (1점)**
- **인정 패턴**: 좌회전과 대칭되는 패턴
- **점수 부여**: 패턴 발견 시 1점

**5-4. 후진/정지 제어 로직 (1점)**
- **인정 패턴**:
  - `back()`, `reverse()`, `stop()` 함수
  - "후진", "뒤", "정지", "halt" 키워드
  - `speed = 0` 또는 "brake"
- **점수 부여**: 패턴 발견 시 1점

#### 왜 이렇게 평가하는가?
주행 제어는 자율주행의 **최종 출력(actuator control)**에 해당합니다. 4가지 기본 동작을 모두 구현해야 완전한 주행 시뮬레이션이 가능합니다. 각 동작을 1점씩 배정하여 **균등한 중요도**를 부여합니다.

### 6. random 생성 후 조건 로직 연결 (1점)

#### 평가 목적
random으로 상황을 생성한 후, 이를 조건문을 통해 제어 로직에 연결했는지 평가합니다.

#### 평가 기준
```python
# 패턴 1: random 직후 if문
sign = random.choice(["stop", "danger", "o_sign"])
if sign == "stop":
    # 처리

# 패턴 2: 함수 분리
def generate_situation():
    return random.choice(...)

def handle_left():
    # 좌측 처리
```

#### 인정 조건
1. `random.` 사용 확인
2. random 호출 후 100자 이내에 `if` 문 존재
3. 또는 random을 사용하는 함수와 처리 함수가 분리되어 있음

#### 왜 이렇게 평가하는가?
이 항목은 **로직의 연결성**을 평가합니다. 단순히 random을 사용하는 것이 아니라, 생성된 랜덤 값을 실제 제어 로직에 연결하는 능력을 확인합니다. 이는 **데이터 흐름(data flow)** 이해도를 측정합니다.

### 7. 코드 품질 (총 3점)

#### 평가 목적
코드의 구조, 가독성, 안정성을 종합적으로 평가합니다.

#### 세부 항목

**7-1. 함수 분리 구조화 (1점)**

| 함수 개수 | 평가 | 점수 |
|-----------|------|------|
| 7개 이상 | 매우 우수 | 1점 |
| 5~6개 | 우수 | 1점 |
| 3~4개 | 양호 | 1점 |
| 2개 이하 | 미흡 | 0점 |

- **평가 기준**:
  ```python
  # 권장 함수 분리 예시
  def generate_random_rect()      # 랜덤 생성
  def detect_position(x)          # 위치 판별
  def calculate_distance(width)   # 거리 계산
  def handle_sign(sign_type)      # 표지판 처리
  def turn_left()                 # 좌회전
  def turn_right()                # 우회전
  def go_forward()                # 전진
  def stop_vehicle()              # 정지
  ```

- **왜 7개 이상인가?**
  - 자율주행 시뮬레이션의 주요 기능을 충분히 분리하려면 최소 7개 이상의 함수가 필요합니다.
  - **단일 책임 원칙(Single Responsibility Principle)**: 각 함수는 하나의 명확한 역할만 수행해야 합니다.
  - 7개 이상의 함수는 코드가 잘 구조화되어 있음을 의미합니다.

**7-2. 의미있는 변수명 사용 (1점)**
- **평가 기준**:
  - 3개 이상의 명확한 변수명 사용
  - 예: `position`, `distance`, `speed`, `angle`, `left`, `right`, `center`, `위치`, `거리`, `방향`
- **왜 중요한가?**
  - 코드의 **자기 문서화(self-documenting code)**
  - 다른 사람이 읽기 쉬운 코드
  - 유지보수성 향상

**7-3. 예외/에러 처리 (1점)**
- **평가 기준**:
  ```python
  # 패턴 1: try-except
  try:
      value = int(input())
  except ValueError:
      value = 0
  
  # 패턴 2: 조건 체크
  if value is None:
      value = default_value
  ```
- **왜 필요한가?**
  - 프로그램의 **안정성(robustness)** 확보
  - 예상치 못한 상황에 대한 대응 능력

#### 왜 클래스 사용 시 더 높은 점수인가?

**1. 객체지향 프로그래밍(OOP)의 가치**
```python
# 절차적 프로그래밍
x = 320
y = 240
width = 100
height = 80

def calculate_distance(width):
    return "far" if width < 90 else "near"

# vs 객체지향 프로그래밍
class Vehicle:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def calculate_distance(self, target):
        # 거리 계산 로직
        pass
    
    def turn_left(self):
        # 좌회전 로직
        pass

class Sign:
    def __init__(self, x, y, width, height, type):
        self.x = x
        self.y = y
        self.width = width
        self.height = height
        self.type = type
    
    def get_position(self):
        if self.x < 213:
            return "left"
        elif self.x < 427:
            return "center"
        else:
            return "right"
```

**객체지향의 장점:**
- **캡슐화(Encapsulation)**: 데이터와 메서드를 하나로 묶음
- **재사용성(Reusability)**: 클래스를 재사용 가능
- **확장성(Extensibility)**: 상속을 통한 기능 확장 용이
- **유지보수성**: 변경 사항이 클래스 내부로 제한됨

**2. 실무 역량 표시**
- 클래스 사용은 **중급 이상의 프로그래밍 능력**을 의미
- 실제 업계에서 선호하는 코딩 스타일
- **설계 능력(design capability)** 보유를 입증

**3. 복잡도 관리**
- 2개 이상의 클래스 사용은 **시스템 설계 능력**을 보여줌
- 예: `Vehicle` 클래스 + `Sign` 클래스 + `Simulator` 클래스
- 각 클래스가 명확한 책임을 가지는 **관심사의 분리(Separation of Concerns)**


**위 코드가 20점을 받는 이유:**
1. **3개의 클래스** 사용 (Sign, Vehicle, Simulator)
2. 각 클래스가 **명확한 책임**을 가짐
3. **객체 간 상호작용**이 잘 설계됨
4. **확장 가능한 구조** (새로운 표지판 타입 추가 용이)
5. **실무 수준의 코드 품질**

### 패턴 매칭 알고리즘

#### 정규표현식 사용
평가는 주로 **정규표현식(Regular Expression)**을 사용합니다.

**예시: X좌표 랜덤 생성 검증**
```python
# 패턴 1: 범위 지정 검증
pattern = r"(x|x_pos|rect_x)\s*=\s*random\.\w+\([^)]*0[^,)]*,[^)]*640"

# 패턴 2: 단순 random 사용 검증
pattern = r"(x|x_pos|rect_x)\s*=.*random"

# 검증
if re.search(pattern, code_text, re.IGNORECASE):
    # 통과
```

#### 유연한 평가
- **대소문자 구분 없음**: `re.IGNORECASE` 플래그 사용
- **다양한 변수명 인정**: x, x_pos, rect_x, pos_x, sign_x 등
- **다양한 함수명 인정**: randint, random, choice 등
- **한글/영문 혼용 인정**: "left", "왼쪽", "좌측" 모두 인정

#### 왜 유연하게 평가하는가?
1. **다양한 코딩 스타일 존중**
2. **창의적 변수명 허용**
3. **실질적인 구현 능력 평가** (형식보다 내용 중시)
4. **학습 과정의 다양성 인정**
